支付系统对接说明书

面向客户公司技术团队，说明如何将信用卡、Stripe、PayPal、支付宝、微信支付等支付能力对接到 Smart Gateway 的充值与订阅体系。

概览 认证与环境 Stripe / 信用卡 PayPal 支付宝 / 微信支付 Waffo / 聚合支付 Creem EPay 订阅套餐 Webhook 规范 交付清单

1. 概览

Smart Gateway 支付体系支持两类业务：用户余额充值（Top-up）与订阅套餐购买（Subscription）。客户侧可以选择直接使用平台内置的 Stripe/Waffo/Creem/EPay，也可以通过自有支付网关把 PayPal、支付宝、微信支付等支付结果回调到平台。

生产地址http://smart-gateway.shop
健康检查GET /healthz
推荐信用卡渠道Stripe 或 Waffo Card Checkout
推荐国内支付渠道通过 EPay/聚合支付接入支付宝、微信支付

正式处理银行卡或钱包支付前，建议将站点升级到 HTTPS，并在支付服务商后台启用 webhook 签名校验。

2. 认证与环境

用户发起支付接口需要登录态 Cookie 和 Smart-Gateway-User 请求头；支付服务商回调接口是公开入口，但必须由服务端使用签名密钥校验。

Cookie: _session=...
Smart-Gateway-User: <user_id>
Content-Type: application/json

管理员配置支付参数时，需使用管理员账号登录后台。管理员账号和初始密码由交付方单独提供，不应写入 Git 仓库或前端代码。

3. Stripe / 信用卡支付

Stripe 是推荐的海外信用卡接入方式，适合 Visa、Mastercard、Amex、Apple Pay、Google Pay 等卡组织或钱包能力。

3.1 Webhook 地址

POST http://smart-gateway.shop/api/stripe/webhook

3.2 用户余额充值

POST /api/user/self/stripe/amount
POST /api/user/self/stripe/pay

示例请求：

{
  "amount": 10,
  "top_up_count": 1
}

3.3 订阅套餐支付

POST /api/subscription/stripe/pay
{
  "plan_id": 1
}

3.4 客户技术需提供

  • Stripe Secret Key
  • Stripe Publishable Key
  • Webhook Signing Secret
  • 结算币种、税务/发票要求、成功/失败跳转页面

4. PayPal 对接

当前平台未将 PayPal 作为内置一等支付渠道，但客户可通过两种方式接入：

方案说明适用场景
聚合支付通过 Waffo/EPay 或客户现有支付网关把 PayPal 订单统一转换为平台充值/订阅回调最快上线
自定义适配器客户侧服务完成 PayPal Orders API 流程，再调用 Smart Gateway 管理端完成额度发放客户已有 PayPal 技术栈

4.1 推荐流程

  1. 客户前端调用客户自有后端创建 PayPal Order。
  2. 用户在 PayPal 完成支付。
  3. 客户后端验证 PayPal webhook / capture 结果。
  4. 客户后端调用 Smart Gateway 管理后台或人工审核接口完成充值/订阅绑定。

5. 支付宝 / 微信支付

支付宝与微信支付建议通过 EPay 或客户已有聚合支付网关接入。平台已提供 EPay 通知与返回入口，可承接扫码支付、H5 支付或聚合支付结果。

5.1 用户充值支付入口

POST /api/user/self/pay
POST /api/user/self/amount

5.2 回调地址

POST http://smart-gateway.shop/api/user/epay/notify
GET  http://smart-gateway.shop/api/user/epay/notify

5.3 订阅回调地址

POST http://smart-gateway.shop/api/subscription/epay/notify
GET  http://smart-gateway.shop/api/subscription/epay/notify
GET  http://smart-gateway.shop/api/subscription/epay/return
POST http://smart-gateway.shop/api/subscription/epay/return

客户技术侧需要确认：商户号、应用 ID、签名密钥、回调白名单、订单号规则、金额单位、幂等处理策略。

10. Webhook 规范

支付回调必须满足以下要求：

  • 必须校验服务商签名，不能只相信前端跳转成功页。
  • 必须按订单号做幂等处理，重复 webhook 不得重复加额度。
  • 金额、币种、用户 ID、套餐 ID 必须与平台订单记录一致。
  • 回调处理成功后返回服务商要求的成功响应。

上线验收建议：创建低金额测试订单，完成支付，确认 webhook 入站，确认余额或订阅被正确发放，再重放 webhook 验证幂等。

  • 生产站点：http://smart-gateway.shop
